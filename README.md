# Cascade PI-based MRAC of a DC-DC boost converter — MATLAB/Simulink recreation

[![Verify recreation](https://github.com/Isttiaak/boost-cascade-pi-mrac/actions/workflows/verify.yml/badge.svg)](https://github.com/Isttiaak/boost-cascade-pi-mrac/actions/workflows/verify.yml)

Recreation of C. Yanarates and Z. Zhou, "Design and Cascade PI Controller-Based Robust Model
Reference Adaptive Control of DC-DC Boost Converter", *IEEE Access*, vol. 10, pp. 44909–44922,
2022, doi:[10.1109/ACCESS.2022.3169591](https://doi.org/10.1109/ACCESS.2022.3169591).

Everything is MATLAB code. The Simulink models are **generated by MATLAB scripts** (Simulink API),
so they can be rebuilt in your own release, reviewed as code and checked automatically. Every push
to `main` runs the whole study on GitHub Actions with MATLAB R2025a (Simulink, Simscape Electrical,
Control System Toolbox, Simulink Control Design), checks the results against the numbers printed
in the paper, and rebuilds the models in the older MATLAB R2022b.

## Quick start (MATLAB)

Everything, exactly as the CI runs it (about 15–25 minutes on a desktop):

```matlab
run_recreation            % results/SUMMARY.md, results/<job>/ (figures, tables, logs), models/*.slx
```

One model by hand:

```matlab
addpath('simulink'); setup_paths();
build_boost_models                                   % builds models/*.slx in your release
boost_mrac_params('vref', [30 40 50], 't_vref', [0.2 0.4]);   % Fig. 18 test: 30 -> 40 -> 50 V
open_system('boost_cascade_pi_mrac_sps')             % or boost_cascade_pi_mrac_diffeq
out = sim('boost_cascade_pi_mrac_sps', 'StopTime', '0.5');
plot(out.v)                                          % also out.iL, out.d, out.theta, out.ym
```

| Product | Needed for |
|---|---|
| MATLAB, Simulink | every model (`diffeq` and `average` plants) |
| Control System Toolbox | the plain-MATLAB recreation in `matlab/` and the Table 6 checks |
| Simscape, Simscape Electrical | the circuit plant `sps` (Specialized Power Systems blocks) |
| Simulink Control Design | `run_frestimate_study` (Section II-A, Fig. 1) |

Tested on GitHub Actions with R2025a (whole study) and R2022b (all models built, six scenarios run).

## Models

| Model | Paper | Contents |
|---|---|---|
| `boost_single_pi_<plant>` | Fig. 8, Eq. 33 | single voltage PI |
| `boost_cascade_pi_<plant>` | Fig. 9, Eqs. 42–43 | outer voltage PI, inner current PI |
| `boost_cascade_pi_mrac_<plant>` | Figs. 10, 12, 19; Eqs. 44, 54–56 | cascade PI scaled by θ from the MIT rule, as written |
| `boost_cascade_pi_mrac_mf_<plant>` | — | same, outer loop tracks the reference-model output (model-following set-point) |
| `boost_openloop_models` | Fig. 7 | circuit, differential-equation and transfer-function models in open loop |
| `boost_frest_<plant>` | Fig. 1, Eq. 2 | duty-to-output plant for `frestimate` |

Plants: `sps` = circuit with Specialized Power Systems blocks (MOSFET, diode, L, C, switched load),
`diffeq` = differential-equation model of Fig. 6, `average` = state-space averaged model (Eqs. 3–9).

Every closed-loop model has the same layout: profiles for V_ref, V_in and the load → discrete
controller (A-D sampling at Ts = 1/(10 f_sw) = 5 µs, Ts·z/(z−1) integrators, Tustin reference
model) → duty-cycle limiter 0…0.9 → PWM modulator (sawtooth at 20 kHz) → plant, with `v`, `iL`,
`d`, `theta`, `ym`, `iref` and `vref` logged every Ts. All parameters live in the struct `BM`
made by `simulink/boost_mrac_params.m`; every model creates it when it opens.

The `.slx` files are not committed: `build_boost_models` makes them for your release in seconds.
Models built by the CI (R2025a) and pictures of every diagram are on the
[`ci-results`](https://github.com/Isttiaak/boost-cascade-pi-mrac/tree/ci-results/ci) branch.

## How it is verified

| CI job | What it runs (all MATLAB) |
|---|---|
| MATLAB reference and paper analysis | `matlab/run_all.m` (equations, Table 6, Figs. 1, 5, 7, 13–18, Table 10); the 21 test scenarios on the plain-MATLAB simulator `matlab/boost_sim.m`; paper checks of Sections II–IV |
| Simulink diffeq / sps | builds every model, runs the 21 scenarios, compares 100+ metrics with `boost_sim.m` and checks them against the paper |
| frestimate | Section II-A with Simulink Control Design at the paper's 0.03 and a small-signal 0.0005 amplitude |
| Older MATLAB (R2022b) | builds every model and runs six scenarios against the reference |
| Summary | `simulink/ci_report.m` writes the run summary and the `ci-results` branch |

The 21 scenarios (`simulink/scenario_list.m`) cover Fig. 7 (open loop), Figs. 13–15
(learning rates), Fig. 16 (load steps), Fig. 17 (load and input steps), Fig. 18 and Table 10
(reference steps) and Figs. 22–24 (the experiment, in simulation), each with the single PI,
the cascade PI and both MRAC variants.

## Known issues in the paper

- Eq. 32 and Eq. 40 divide only some coefficients of Eqs. 31 and 39 by 80. Evaluated correctly,
  Eq. 31 has a lightly damped LC resonance (ζ ≈ 0.03 at 2384 rad/s) and a RHP zero at
  40 000 rad/s; Table 6 was computed from the printed versions.
- The printed Eq. 51 numerator (−0.0625 s) makes the reference loop unstable; −0.00625 s follows
  from Eq. 31 and Table 8 and is used here.
- The single PI of Eq. 33 is unstable on the lossless converter and settles into a limit cycle;
  small device losses (Simscape Electrical's default MOSFET and diode) stabilise it.
- Eqs. 54–56 as written make the MRAC behave like the plain cascade PI at γ = 0.04; the paper's
  MRAC step response (Table 10) needs the model-following set-point.
- The paper's frequency-response procedure (sinestream amplitude 0.03) gives a well-damped
  resonance, not Eq. 2's real poles and RHP zero at 474 rad/s.
